# سوقي — منصة تجارة إلكترونية متعددة المتاجر

**Next.js 15 (App Router) · React 19 · TypeScript · Tailwind · Supabase (Postgres + RLS + Auth + Storage + Realtime) · three.js**

سوق موحد، سلة واحدة، دفعة واحدة؛ والمنصة تدير تعدد المتاجر في الخلفية (طلب رئيسي + طلب فرعي مستقل لكل متجر).

## التشغيل
```bash
cp .env.example .env.local   # ضع رابط المشروع والمفتاح المنشور
npm install
npm run dev
```

## بنية الكود
```
src/
  app/
    (shop)/        واجهة العميل: الرئيسية، البحث، التصنيف، المنتج، المتجر، السلة، الدفع، حسابي، ابدأ البيع
    auth/          الدخول، التسجيل، الاستعادة، التحقق الثنائي، callback
    merchant/      لوحة التاجر: الطلبات (لحظية)، المنتجات، المخزون، المرتجعات، الخصومات والكوبونات، التسويات، الفريق، ملف المتجر
    admin/         لوحة الإدارة: المؤشرات، العمليات وتأكيد التسليم OTP، المتاجر، مراجعة الكتالوج، المستخدمون والأدوار، التصنيفات، المحتوى، الكوبونات، المالية، التقييمات، الإعدادات، سجل التدقيق
  components/
    ui/            مكونات أساسية (Button, Badge, Field, Modal, Rating...)
    shop/          مكونات الواجهة (Header, ProductCard ثلاثية الأبعاد، Hero...)
    dashboard/     مكونات اللوحات (Shell, Widgets, StatusActions, ProductForm...)
    three/         مشهد three.js الخفيف
  hooks/           الجلسة، جلب البيانات، سياق المتجر، الإضافة للسلة
  lib/             عملاء Supabase، طبقة API، التحقق (zod)، التنسيق، الحالات
  stores/          سلة الزائر (zustand)

```

## الأمان (ملخص)
- **RLS مفعّلة ومفروضة (FORCE) على كل الجداول**، ولا صلاحيات افتراضية: كل GRANT صريح.
- العمليات الحساسة (التسعير، إنشاء الطلب، حجز المخزون، تغيير الحالات، التسويات، الأدوار) **دوال SECURITY DEFINER** بمسار بحث فارغ، وتتحقق من الدور والانتقال المسموح داخل قاعدة البيانات.
- **السعر لا يُقبل من المتصفح** — يُحسب في `compute_cart` ويُعاد حسابه داخل معاملة `place_order` مع خصم ذري للمخزون (`UPDATE ... WHERE qty_available >= qty`) ومفتاح idempotency.
- الدوال المساعدة في مخطط `private` غير المعروض عبر الـ API.
- لا يُستخدم مفتاح `service_role` في الواجهة إطلاقًا؛ الواجهة تستخدم المفتاح المنشور فقط.
- رمز التسليم OTP لا يراه إلا صاحب الطلب؛ عدّاد محاولات بحد 5.
- المستخدم لا يستطيع ترقية نفسه (صلاحيات أعمدة: لا يعدّل إلا الاسم/الهاتف). الأدوار الإدارية يمنحها المدير العام فقط، ولا يمكن سحب آخر مدير عام.
- التحقق الثنائي TOTP مدعوم؛ إذا فعّله المسؤول تصبح كل الإجراءات الإدارية مشروطة بجلسة aal2.
- رفع الصور: نوع وحجم + فحص التوقيع الفعلي (magic bytes) + أسماء عشوائية + سياسة تخزين تحصر كل متجر في مجلده.
- سجل تدقيق إضافة-فقط، وسجلات المخزون والحالات غير قابلة للتعديل أو الحذف. لا حذف فعلي للسجلات التاريخية (أرشفة).
- رؤوس أمان: CSP صارمة، HSTS، X-Frame-Options، Referrer-Policy، Permissions-Policy.
- حماية من إعادة التوجيه المفتوح، وتهريب JSON-LD، وحدود معدلات على الطلبات والبحث.

## ما يُشغَّل يدويًا في هذا الإصدار (وفق القسم 4 من التحليل)
الدفع عند الاستلام (الدفع الإلكتروني ينتظر قرار مزود الدفع)، تعيين المندوب يدويًا من لوحة العمليات، التحويل البنكي للتجار يُسجَّل يدويًا بعد اعتماد التسوية.

## الاستوري (حالات وعروض المتاجر)
- **التفعيل:** من لوحة الإدارة ← «اشتراكات الاستوري» ← «تفعيل شهر» (30 يومًا تبدأ لحظة التفعيل). التفعيل لمتجر مشترك يمدّد اشتراكه من تاريخ انتهائه. «إيقاف» يخفي حالاته فورًا. يصل إشعار لصاحب المتجر في الحالتين.
- **النشر:** لوحة التاجر ← «الاستوري»: صورة (JPG/PNG/WebP حتى 5MB) أو فيديو (MP4/WebM حتى 30 ثانية و20MB)، نص حتى 200 حرف، ربط اختياري بمنتج، ومدة ظهور 24 ساعة أو 3 أيام أو 7 أيام. الحد: 15 حالة نشطة لكل متجر.
- **العرض:** شريط «حالات المتاجر» في الرئيسية وصفحة المتاجر يعرض كل المتاجر ذات الاشتراك الساري، وعارض بملء الشاشة بأسلوب إنستغرام (لمس يسار/يمين، ضغط مطوّل للإيقاف، سحب للأسفل للإغلاق).
- **الأمان:** الكتابة عبر دوال محمية فقط (`merchant_add_story`, `admin_grant_story`...). التخزين في حاوية `stories` ولا يرفع المتجر إلا داخل مجلده وبوجود اشتراك ساري. عدد المشاهدات لا يظهر إلا للتاجر.
- **صلاحية الفريق:** يمكن منح موظف صلاحية «الاستوري» فقط من صفحة الفريق.
- الملفات: `supabase/migrations/0011_stories.sql`، `src/components/stories/*`، `src/app/merchant/stories`، `src/app/admin/stories`.
